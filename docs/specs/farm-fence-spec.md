# 農場圍籬（原地分組）架構規格與技術驗證書 (Farm Fence Specification)

> **版本**：v1.0.0 (PoC 驗證閉環)  
> **核心哲學**：**原檔與原捷徑留在原處，原桌面圖示就是圍籬內的圖示，不另外建立第二個入口。**

---

## 概述與設計宗旨

傳統桌面框工具（包含既有版本）多採用「虛擬面板投影」模式：整體隱藏 Windows 原生桌面圖示，在 WPF 面板內部自主繪製圖示圖片與文字。此模式雖然具備豐富的 UI 控制力，但也衍生出重複捷徑維護、檔案異動延遲、圖示快取 GDI 負擔以及異常結束時桌面圖示失蹤等本質缺陷。

**「農場圍籬（原地分組）」** 方案回歸桌面組織工具之正統核心：
- **原檔不動**：不執行實體檔案之複製、搬移或刪除。
- **零第二入口**：桌面圖示依然是 Windows Explorer 原生圖示，不建立第二份副本。
- **原生互動穿透**：圍籬外框僅作視覺分組與網格定位，點擊、框選、多選、右鍵選單 100% 由 Windows Explorer 原生處理。
- **無負座標與退出安全**：即使程式強制結束或崩潰，圖示依然留於原位，系統具備 100% 可用性。

### 關鍵技術突破與驗證細節：
1. **項目精準辨識**：同時解析個人桌面（`UserDesktop`）與公用桌面（`CommonDesktop`），完整支援中文字元、資料夾、`.lnk` 捷徑、`.url` 網路連結與系統虛擬項目（如回收筒、控制台）。
2. **零第二入口實證**：抽樣實體檔案比對 SHA256 雜湊，證明排版前後實體檔案內容、屬性與路徑 100% 相同。
3. **客戶區完全穿透**：WPF 視窗透過 `WM_NCHITTEST` 攔截，內容區回傳 `HTTRANSPARENT (-1)`，標題列支援拖曳移動，而框內滑鼠點擊、框選、右鍵完全穿透給底層 Windows Explorer。
4. **拖曳移動剛體聯動**：外框移動向量 $(\Delta X, \Delta Y)$ 時，內部所有納管圖示同步以微批次完成實體像素座標平移。
5. **重要前置條件確認**：實測確認若 Windows 開啟「自動排列圖示（AutoArrange: True）」，Explorer 會強制將圖示鎖定於左側。因此農場圍籬生效之前提，為使用者需取消勾選桌面「自動排列圖示」。

## 四、分頁、收合與捲動的物理邊界與工程處方

原生桌面圖示是繪製在全螢幕 `SysListView32` 畫布上，Windows Shell **並未提供局部圖示視覺剪裁（Sub-region Clipping）API**。針對進階面板行為，採取以下務實且可落地的工程對策：

```
       功能           底層限制                  最佳工程處方 (收斂方針)
   ──────────   ────────────────────   ────────────────────────────────────────
   1. 捲動       超出框外的圖示無遮罩   捨棄微型捲軸，採用「自適應網格容量」或「拉大圍籬」
   2. 收合       無單一圖示隱藏 API     採「抽屜式邊界折疊」；或維持穩定展開態
   3. 分頁       單一區域無法隱藏圖示   對齊為「多個獨立圍籬並存」，捨棄框內 Tab 切換
```

1. **捲動（Scrolling）對策**：
   - 圍籬尺寸採「網格容量自適應」。加入圖示時外框自動向下長高一格，或由使用者調整外框大小以容納圖示，避免圖示超出外框產生破圖。
2. **收合（Roll-up）對策**：
   - 嚴禁使用螢幕外負座標。收合時可將圖示聚攏於標題列後方，或初始版本優先提供純展開態，確保最高穩定性。
3. **分頁（Tabs）對策**：
   - 「農場圍籬」天生適合於桌面同時擺放多個不同主題的圍籬（如「待辦」、「專案檔案」、「工具」），多圍籬並存比在單一微型框內切換分頁更清晰高效。

## 五、正式實作與整合原則

1. **既有主要功能 100% 保留**：
   - 既有 Data Frame、Portal Frame、Notes 便箋維持正常運作，互不排斥。
   - 舊版設定檔格式（`frames.json`, `options.json`, `notes.json`）維持向下相容。
2. **原地分組邊界**：
   - 原地分組先限於使用者桌面與公用桌面的項目。
   - 非桌面項目維持原有加入行為。
3. **故障安全第一**：
   - 程式無預警關閉時，桌面圖示完全可用，不以隱藏全體圖示或建立捷徑作為備援。
