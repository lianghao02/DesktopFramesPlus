# 🏆 v2.11.1 里程碑：面板穩定性修正與拆檔

v2.11.1 修正 7 項既有問題，包含**隱藏的面板開啟程式後又自己出現**、**新建面板在重開前讀不到自己的設定**，以及**同名面板互相干擾隱藏與還原**。同時在不改變行為的前提下，把 10,900 行的 `FrameManager.cs` 拆成 18 個檔案，讓之後的修改更容易定位與驗證。

這些問題大多藏在長年累積的單一大方法裡，平時不容易察覺。本版先為面板的建立、選單、拖放、捲起與隱藏補上回歸測試，再逐段拆分；拆分過程中由測試與外部審查找出問題，每項修正都先寫出會失敗的測試，再修到通過。

## ✨ 重點更新特色

🛡️ **隱藏的面板維持隱藏**
- 建立面板時第一次顯示就已隱藏並加入系統匣清單，但流程最後又顯示一次；現在會跳過設定為隱藏的面板。
- 系統匣「已隱藏」清單與畫面一致，從系統匣可正常叫回。

🔍 **新建面板讀得到自己的設定**
- 執行中新建的面板資料格式與從設定檔讀入的不同，原本讀取設定時一律得到空字串。
- 修正後不用重開程式：**Ctrl＋滾輪調整圖示大小**、圖示大小選單的目前勾選、篩選列初始值、收納資料夾改路徑時的原名稱都正常。

🧩 **同名面板各自獨立**
- 系統匣隱藏清單、還原、刪除與「重新載入」後的重新隱藏，改以面板 `Id` 辨識，標題只用於顯示。
- 原本同名面板只留一個還原入口，可能還原到另一個面板。

⚡ **局部重建時停止舊的資料夾監看**
- 從系統匣還原或局部重建資料夾／收納面板時，先停止舊的 `FileSystemWatcher` 與延遲計時器再移除，避免背景監看累積。

🎨 **自訂外框顏色恢復作用**
- Q 版木框是點陣圖，原生邊框看不到；改為在木框內緣畫出所選顏色的描邊，粗細沿用「外框粗細」（0 表示不畫）。
- 建立面板與「自訂外觀」即時修改使用同一套繪製，重開後仍保留；未設定顏色的面板外觀不變。

🔧 **其他修正**
- 圖示右鍵的「開啟目標所在資料夾」原本誤顯示為「開啟收納資料夾」。
- 以 `control` 開頭的一般檔名不再被當成控制台指令而略過「目標是否存在」的檢查。

📦 **FrameManager 拆檔（行為不變）**
- `partial class` 分為 18 個檔案；`CreateFrame` 由約 3,715 行拆成約 200 行的建構流程與 18 個建構方法。
- 每一步建置並通過全部測試；與拆分前比對，原有程式只改 30 行（全為預期的變數改存與宣告調整），其餘逐字保留。

## 使用與更新

下載 `DesktopFramesPlus-v2.11.1-zh-TW.zip`，解壓縮完整資料夾後執行 `Desktop Frames.exe`，不要只取 EXE。從舊版更新時先結束程式並備份 `Profiles/`，只替換程式檔，不要覆蓋或刪除個人設定。設定檔格式與 v2.11.0 相容。

## 驗證與限制

- Visual Studio MSBuild 自包含發布通過；成品 DLL 版本 `2.11.1.0`。
- 對 `PortablePublish` 成品執行：隔離驗收與代表性測試 **251 項**全過、專用收納面板合成測試 **10 項**全過、繁中資源 100% 覆蓋。
- 對新抽出的方法做故意改壞抽查：7 種中 6 種被測試抓到，未抓到的 1 種為等價變異（該變數從未被讀取）。
- ZIP 480 個檔案，不含 `Profiles`、PDB、記錄檔或驗收標記。
- **尚未完成桌面手動驗收**：使用者以手機遠端指示先發布。單擊標題改名、拖曳移動、按住 Ctrl／Alt 拖入、Ctrl＋滾輪、外框描邊的實際觀感、同名面板還原等需在實體桌面確認，清單見 `IMPLEMENTATION_PLAN.md`。
- 不同電腦、無全域 .NET 的乾淨環境、Windows 10、ARM64、多螢幕／DPI 尚未實測；32 位元 Windows 不適用。企業防毒相容性不作保證。
- 沒有啟用 CI。
