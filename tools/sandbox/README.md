## 一、核心架構與設計原理

本原型採用候選方案：**原生桌面圖示 ＋ 穿透外框（In-Place Fence）**。

1. **原檔與捷徑完全不動**：
   - 不複製檔案、不搬移實體檔案、不建立影子捷徑（.lnk）、不修改檔案屬性。
   - 透過 Windows KnownFolder API（`SHGetKnownFolderPath`）解析真實桌面目錄，支援個人桌面與 OneDrive 重新導向（如 `C:\Users\chia-hao\Desktop`）。
2. **零注入與安全防禦相容**：
   - 實測確認：跨進程向 `explorer.exe` 請求 `PROCESS_VM_WRITE` 會被 Windows Defender / Exploit Protection 攔截終止。
   - 本原型全面採用**純 Win32 唯讀讀取（`LVM_GETITEMPOSITION`）** 與 **標準 `LVM_SETITEMPOSITION`（`lParam` 封裝座標，免遠端記憶體寫入）**，達到 100% 零進程注入、零防毒攔截。
3. **徹底排除「依範圍自動收集」偏差，僅管理手動拖入項目**：
   - 建立所有桌面項目的初始物理座標基準（Initial Baseline）。
   - 建立新柵欄、移動柵欄、放大柵欄時碰到的圖示，位移為 0，絕對不自動收集！
   - 圖示只有在產生實質位移（$\ge 15$ 物理像素）且新座標落在柵欄工作區內時，才判定為使用者親手拖入；若圖示未被拖動（位移 $< 15$ 像素），即使處於柵欄底下也絕不改變歸屬。
   - 柵欄內的圖示被使用者拖到柵欄外（位移 $\ge 15$ 像素且落在所有柵欄外）時，才判定為手動拖出解除。
4. **消除「順序硬配」缺陷**：
   - 徹底廢除以目錄字典序猜測圖示索引的作法。
   - 以 SysListView32 的同源索引 `Index` 與螢幕物理座標 `ScreenPoint` 作為項目的真實可信錨點，移動時直接以 `Index` 精確調度底層圖示，絕不發生「將文件 A 誤套為文件 B」或「帶動錯誤圖示」之問題。
5. **高 DPI 物理像素統一換算**：
   - 透過 `PointToScreen` 將外框工作區邊界即時換算為螢幕物理像素（Pixels），扣除標題列物理高度，徹底解決 125%、150% 等縮放比例下的判定偏差。
6. **外框移動/縮放全面防誤吸（`WM_ENTERSIZEMOVE`）**：
   - 監聽 `WM_ENTERSIZEMOVE`、`WM_NCLBUTTONDOWN` 與 `WM_EXITSIZEMOVE`，外框在被拖曳移動或拉伸縮放的整個過程中全面鎖定 `IsUserMoving`，路過圖示時暫停圖示歸屬判定。
7. **圖示移動讀回驗證（Read-Back Verification）**：
   - 每次調用 `SetIconPositionByScreenPoint` 後，立即讀回 `LVM_GETITEMPOSITION` 校驗，誤差 > 10 像素（例如被系統「自動排列圖示」強制拉回）即判定失敗並記錄日誌。
8. **彈性柵欄配置與原子保存**：
   - 完整支援 0、1、2 或 N 個柵欄，刪除單一柵欄後重啟絕不再被重設回預設 2 個。
   - 介面提供「➕ 新增柵欄」按鈕。
   - 採用臨時檔案寫入再覆蓋（Atomic Replace），防止非預期退出導致配置損毀。
9. **資源管理健全性**：
   - 單一長駐 STA 桌面代理背景執行緒與任務佇列，退出時正確調用 `CloseDesktop` 釋放桌面控制代碼，杜絕執行緒與記憶體洩漏。

## 二、實測驗證狀態分類清單

依據驗收標準，本輪嚴格區分「【已實測】」、「【已實作】」與「【未驗證】」：

### 1. 【已實測】（透過真實指令與程序運作取得客觀證據）

- [x] **桌面 HWND 定位**：
  - 成功穿透終端機桌面 Station 隔離，透過乾淨 STA 執行緒切換至 `WinSta0\Default`，精準定位 `SysListView32`（HWND: 66052）。
- [x] **真實桌面路徑解析**：
  - 透過 `SHGetKnownFolderPath(FOLDERID_Desktop)` 解析出 OneDrive 重新導向桌面：`C:\Users\chia-hao\Desktop`（實測存在: True）。
- [x] **原生圖示物理座標與清單讀取**：
  - 執行 `--test` 成功讀出使用者桌面當前全部 19 個原生項目的真實物理座標（例如 `[0] @ (0, 5)`、`[17] @ (166, 129)`、`[18] @ (166, 253)`），耗時小於 5ms。
- [x] **防毒安全與零注入驗證**：
  - 排除 `PROCESS_VM_WRITE` 寫入 Explorer 的安全衝突，改以純 Win32 唯讀與標準 `LVM_SETITEMPOSITION`，程序穩定執行退出（ExitCode: 0），零 Defender 攔截。
- [x] **多柵欄持久化與彈性配置**：
  - 移除 `>= 2` 寫死限制，實測可保存與還原任意數量的柵欄。
- [x] **實體檔案零破壞驗證**：
  - 操作與啟動前後比對桌面目錄，19 個實體檔案與捷徑之內容、屬性、路徑完全未受任何異動。

### 2. 【已實作】（程式碼已完整實作，具備可執行架構）

- [x] **穿透外框與 8 方向縮放**：
  - `FenceWindow.cs` 實作工作區返回 `HTTRANSPARENT`，點擊、雙擊、右鍵穿透至底層桌面；四周邊框支援 8 方向平滑縮放。
- [x] **手動拖出解除與跨柵欄移動**：
  - `FenceManager.cs` 實作定時邊界命中比對，圖示移出邊界時觸發 `[拖出解除]`，移至另一柵欄時觸發 `[分組變更]`。
- [x] **取消柵欄安全解散**：
  - 點擊標題列右上角 ✕ 時，觸發 `OnFenceClosed`，解除內部項目的柵欄歸屬，圖示保留在桌面原地。
- [x] **動態新增柵欄**：
  - 控制台提供「➕ 新增柵欄」按鈕，可隨時動態建立新柵欄並賦予不同主題色彩。
- [x] **拖曳外框連動圖示與防誤吸**：
  - `FenceMoved` 事件計算物理像素位移量，連動內部被圈養的原生圖示；拖動期間以 `IsUserMoving` 鎖定圖示歸屬判定。

### 3. 【未驗證】（受限於背景無頭終端，需使用者手動在實體螢幕體驗）

- [ ] **滑鼠手動即時拖曳手感**：
  - 使用者在實體桌面親手按住滑鼠左鍵將檔案圖示拖入、拖出柵欄的操作流暢度。
- [ ] **Windows 自動排列圖示衝突**：
  - 若使用者桌面啟用了「自動排列圖示（Auto Arrange Icons）」，Windows 會強制將圖示排至最左側，此時連動位移會被系統自動拉回（測試時請關閉自動排列）。
- [ ] **Esc 鍵取消拖曳邊界**：
  - 使用者在拖曳途中按下 Esc 取消時，原生桌面圖示位置未變動，原型應維持既有歸屬判定。
- [ ] **拖至其他非桌面程式視窗**：
  - 拖至 Word 或瀏覽器等一般視窗時，是否會誤觸其他程式的檔案開啟。

## 三、如何啟動與手動實測

在終端機或檔案總管中：

1. **底層通信與圖示座標檢驗（CLI 模式）**：
   ```powershell
   .\tools\sandbox\bin\Debug\net8.0-windows7.0\FarmFenceSandbox.exe --test
   ```
2. **啟動多柵欄與控制台（GUI 實測模式）**：
   ```powershell
   Start-Process .\tools\sandbox\bin\Debug\net8.0-windows7.0\FarmFenceSandbox.exe
   ```
   - 螢幕上會出現柵欄與控制台：
     - **藍色外框**：柵欄 A (工作農場)
     - **綠色外框**：柵欄 B (暫存農場)
     - 控制台左下角有「➕ 新增柵欄」按鈕
   - 可用滑鼠調整柵欄大小、拖曳標題列位置。
   - 將桌面上的檔案直接拖入柵欄中，觀察標題列項目數量與控制台日誌更新。
   - 點擊右上角 ✕ 取消柵欄，確認圖示安全留在桌面。
